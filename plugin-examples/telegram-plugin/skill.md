# Skill: Telegram Plugin

**Name:** TelegramNode
**Version:** 2.0.0
**npm package:** telegram-plugin-flow-requests
**CDN (browser):** https://unpkg.com/telegram-plugin-flow-requests@2.0.0/dist/bundle.js
**CDN (server):** https://unpkg.com/telegram-plugin-flow-requests@2.0.0/dist/deno-bundle.js
**Library name:** TelegramNode

---

## Description

Sends a text message to a Telegram chat using the
[Telegram Bot API](https://core.telegram.org/bots/api#sendmessage)
(`POST https://api.telegram.org/bot<token>/sendMessage`).

Provide a bot token (from [@BotFather](https://t.me/BotFather)), a target chat
ID, and the message text. The plugin automatically splits messages longer than
2 000 characters into multiple sequential chunks so they stay within Telegram's
per-message size limits.

Use this node whenever a flow needs to push a notification, alert, or report
to a Telegram channel, group, or private chat.

---

## When to use this plugin

- Send a notification when a workflow completes or fails.
- Deliver a formatted report generated by a previous AI or Code node.
- Alert on-call engineers when a monitored API returns an error status.
- Forward data from a webhook trigger to a Telegram channel.
- Stream long AI-generated text to a chat by letting the plugin chunk it automatically.

---

## Node properties (settings)

| Property name | Type | Required | Default | Description |
|---------------|------|----------|---------|-------------|
| `botToken`    | text | yes      | —       | Telegram Bot API token from @BotFather. Store in env and reference with `{{ state.envData.TELEGRAM_BOT_TOKEN }}`. |
| `chatId`      | text | yes      | —       | Target chat ID (group, channel, or private chat). Store in env and reference with `{{ state.envData.TELEGRAM_CHAT_ID }}`. |
| `message`     | text | yes      | —       | The text to send. Supports `{{ }}` expressions. Messages longer than 2 000 characters are split automatically. |

### How to obtain a `chatId`

1. Add your bot to the target chat or start a private conversation.
2. Send any message to the chat.
3. Call `https://api.telegram.org/bot<token>/getUpdates` — the `chat.id` field
   in the response is the value to use.

For channels, prefix the ID with `-100`, e.g. `-1001234567890`.

---

## Output shape

Success:
```json
{
  "ok": true
}
```

The plugin does not return the Telegram message ID or timestamp. If you need
confirmation details, check the Telegram Bot API response directly.

Failure (API-level error):
```json
{
  "ok": false,
  "error": "Bad Request: chat not found"
}
```

Failure (missing settings — throws before sending):

The node throws with one of:
- `"Invalid settings. You need to provide a bot token"`
- `"Invalid settings. You need to provide a chat ID"`
- `"Invalid settings. You need to provide a message"`

---

## How to reference output in downstream nodes

```
{{ steps.sendMessage.output.ok }}      — boolean, true on success
{{ steps.sendMessage.output.error }}   — error message on failure
```

## Example flow snippets

Send a static notification:

```json
{
  "type": "TelegramNode",
  "name": "notify",
  "setting": {
    "botToken": "{{ state.envData.TELEGRAM_BOT_TOKEN }}",
    "chatId": "{{ state.envData.TELEGRAM_CHAT_ID }}",
    "message": "Workflow completed successfully."
  }
}
```

Send a dynamic message built from a previous node's output:

```json
{
  "type": "TelegramNode",
  "name": "alertOnError",
  "setting": {
    "botToken": "{{ state.envData.TELEGRAM_BOT_TOKEN }}",
    "chatId": "{{ state.envData.TELEGRAM_CHAT_ID }}",
    "message": "Error in flow: {{ steps.httpNode.output.error }}"
  }
}
```

Forward an AI-generated summary (possibly long) to a channel:

```json
{
  "type": "TelegramNode",
  "name": "sendSummary",
  "setting": {
    "botToken": "{{ state.envData.TELEGRAM_BOT_TOKEN }}",
    "chatId": "-1001234567890",
    "message": "{{ steps.aiNode.output.data.choices[0].message.content }}"
  }
}
```

## Constraints and caveats

- **Bot token is sensitive** — always store it as `TELEGRAM_BOT_TOKEN` in the
  flow's environment variables. Never hardcode it in the node settings.
- **Chat ID is required** — the bot must have already been added to the target
  group/channel or the user must have started a conversation with the bot before
  a message can be sent.
- **Automatic chunking** — messages over 2 000 characters are split and sent as
  multiple sequential API calls. This may result in several messages appearing
  in the chat. There is no way to disable chunking.
- **Plain text only** — the plugin sends messages with no `parse_mode`. HTML
  and Markdown formatting are not applied. To enable formatting, a custom
  version of the plugin with a `parseMode` property would be needed.
- **No delivery confirmation** — the output is `{ ok: true }` as long as the
  final chunk is sent without error. Individual chunk failures are silently
  ignored in the current implementation.
- **Rate limits** — Telegram enforces rate limits (generally 30 messages per
  second to different chats, 1 per second to the same chat). High-volume flows
  may need a delay node between sends.
